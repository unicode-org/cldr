# UTS #35 Currency Formatting Specification — Test Data Coverage Verification

This document provides a reproducible, sentence-by-sentence verification of test data coverage for the currency formatting specification in **UTS #35: Unicode LDML, Part 3: Numbers** ([`docs/ldml/tr35-numbers.md`](../../../docs/ldml/tr35-numbers.md)).

For each deep-linked currency section in UTS #35:
1. We link directly to the specification anchor in [`docs/ldml/tr35-numbers.md`](../../../docs/ldml/tr35-numbers.md), with its line range at the pinned commit.
2. We quote the exact normative snippet.
3. We break down every normative sentence/clause in the snippet into the exact **`(dimension = value)` combinations** required to exercise that behavior, with the expected result derived from the CLDR data.
4. We compare the required `(dimension = value)` combinations against the test data generated by `GenerateCurrencyFormatTestData.java` (PR [#5808](https://github.com/unicode-org/cldr/pull/5808)), citing a witness row from the TSV files or recording what is missing.

The generator produces 12 styles (valid combinations of `currency_format_length`, `currency_format_type`, and `currency_display`). The specification selects patterns differently for 4 classes of styles:

| Class | `currency_format_length` | `currency_format_type` | `currency_display` | Pattern used |
| :---: | :--- | :--- | :--- | :--- |
| **A** | `""` | `standard`, `accounting` | `symbol`, `symbolNarrow`, `code` | `currencyFormat` pattern containing `¤` |
| **B** | `short` | `standard` | `symbol`, `symbolNarrow`, `code` | compact `currencyFormat` pattern containing `¤` |
| **C** | `""` | `standard` | `name` | `decimalFormat` pattern + `unitPattern` |
| **D** | `""` | `standard`, `accounting` | `noCurrency` | `currencyFormat` `alt="noCurrency"` pattern (no `¤`) |

### 1.1 Verbatim Specification Snippet (`docs/ldml/tr35-numbers.md`)

> <a name="Currency_Symbols_Decimal_Group"></a>**currencyDecimal**
>
> > Optional. If specified, then for currency formatting/parsing this is used as the decimal separator instead of using the regular decimal separator; otherwise, the regular decimal separator is used.
>
> **currencyGroup**
>
> > Optional. If specified, then for currency formatting/parsing this is used as the group separator instead of using the regular group separator; otherwise, the regular group separator is used.

### 1.2 Sentence-by-Sentence `(Dimension / Value)` Coverage Breakdown

**CLDR data.** `git grep -n -E "<currency(Decimal|Group)[ >]" -- common/main` finds exactly two locales. Neither has child locales or `parentLocales` entries.

| Locale | Monetary separator | Regular separator | Other relevant data |
| :--- | :--- | :--- | :--- |
| `fr_CH` | `<currencyDecimal>.</currencyDecimal>` | `<decimal>,</decimal>` (inherited from `fr`) | Own `<group>'</group>` (U+0027, added by CLDR-13986) |
| `de_AT` | `<currencyGroup>.</currencyGroup>` | `<group draft="contributed"> </group>` / `"\u00A0"` | `<decimal>,</decimal>` (inherited from `de`). With approved data only, `group` is inherited as `.` from `de`, and the override cannot be observed. |

### 1.4 Notes

* **Spec unclear** ([CLDR-19825](https://unicode-org.atlassian.net/browse/CLDR-19825)): L271/L275 apply the monetary separators to all currency formatting, L703 applies them only when `¤` is in the pattern, and L998 step 5 mentions only `currencyDecimal`. ICU4J applies both overrides in all 12 styles.
* **`noCurrency` in PR #5808**: ICU4J `UnitWidth.HIDDEN` removes `¤` from the standard pattern but keeps the space next to it (for example `-1.230,05 ` / `"-1.230,05\u00A0"` for `de`), instead of using the `alt="noCurrency"` pattern. Section 5 (`#currency-noCurrency`) covers this.
* **Compact grouping**: TR35 L454 (a compact pattern of `"0"` falls back to the non-compact pattern) and L752 (`minimumGroupingDigits` is 1 for `de`) suggest `-€ 1.230` for `de_AT` −1230.05, while ICU4J prints `-€ 1230`. Section 2 (compact currency formatting) revisits this.
